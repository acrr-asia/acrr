The main intractability of high-dimensional Bayesian inference, as mentioned earlier in the book, stems from the difficulty of computing the normalizing constant of the posterior distribution: the *marginal likelihood* (or *evidence*). While the MCMC methods presented before circumvent this problem by allowing us to sample from an *unnormalized* posterior distribution, the Laplace approximation offers the benefit that we can compute this quantity in closed form due to the Gaussianity. This not only enables inference and predictions (as shown in the previous chapters), but has one additional important use case: *model selection*. In this chapter, we will motivate why the marginal likelihood is a useful model selection criterion, explain how it is computed with the Laplace approximation, and present several practical use cases for model selection in Bayesian deep learning.

## 1. Marginal likelihood for model selection

There are several perspectives to understand why the marginal likelihood can be a useful criterion for model selection. We will review some different ones in this section to hopefully convince you that this pesky normalization constant is not only a nuisance but a powerful tool when wielded in the right way.

### 1.1 Hierarchical Bayes

Let us look at the familiar Bayes' rule, but with an explicit conditioning on our model of choice, which we will denote by $\mathcal{M}$. This model can encompass both the prior and the likelihood, so in the case of Bayesian deep learning, for instance, the neural network architecture, the likelihood noise level, the prior variance, or its distributional form. In short, the model $\mathcal{M}$ contains everything we have to choose actively before we can start to perform inference. The model-conditioned Bayes' rule looks like this:

$$
p(\theta \mid \mathcal{D}, \mathcal{M}) = \frac{p(\theta \mid \mathcal{M})\, p(\mathcal{D} \mid \theta, \mathcal{M})}{p(\mathcal{D} \mid \mathcal{M})} \tag{11.1}
$$

If we assume now that we do not actually know how to select the model in advance and would like to be Bayesian about it, we could attempt to treat $\mathcal{M}$ as a random variable in a hierarchical Bayesian model, the posterior of which would take the form

$$
p(\mathcal{M} \mid \mathcal{D}) = \frac{p(\mathcal{M})\, p(\mathcal{D} \mid \mathcal{M})}{\int p(\mathcal{M})\, p(\mathcal{D} \mid \mathcal{M})\, \mathrm{d}\mathcal{M}} \tag{11.2}
$$

If we further assume that *a priori*, we do not have any preference for any particular model, that is, $p(\mathcal{M})$ is uniform across models (brushing under the rug the fact that this may be an improper prior if the space of models is not integrable), this yields

$$
p(\mathcal{M} \mid \mathcal{D}) \propto p(\mathcal{D} \mid \mathcal{M}) \tag{11.3}
$$

We now see that the hierarchical posterior over models is proportional to the marginal likelihood term in Equation 11.1. Therefore, if we want to select the model that maximizes the posterior (i.e., a MAP estimate over models), we just need to optimize $\mathcal{M}$ with respect to the marginal likelihood! Since this is essentially just performing a maximum likelihood selection on the second level of this Bayesian hierarchy, it is also often called *maximum likelihood II (ML-II)* model selection.

### 1.2 Occam's razor

Apart from the interpretation as maximum likelihood in a hierarchical Bayesian model, we can also motivate from first principles why the marginal likelihood as a model selection criterion leads to an automatic *Occam's razor* effect. The principle of Occam's razor states that among a set of hypotheses (or models) that explain the same data equally well, one should always prefer the simplest one. The connection to the marginal likelihood has already been made in David MacKay's popular textbook, based on his thesis, and has been further developed by Rasmussen and Ghahramani.

The argument is relatively simple: since the term $p(\mathcal{D} \mid \mathcal{M})$ has to be a normalized distribution over all possible data sets $\mathcal{D}$ for any given model $\mathcal{M}$, this means that models can either assign a lot of likelihood to a small number of data sets or a small amount of likelihood to many data sets. The former would intuitively be a *simple* model, such as a linear one, whereas the latter would be a *complex* model, such as a large neural network. For a data set that can be modeled well by a linear function, the linear model will therefore be able to assign a larger likelihood than the neural network, because its likelihood is not distributed over all the nonlinear data sets. Generally, this means that the model with the largest marginal likelihood for a given data set will typically be a model that is just complex enough to model this data set, but not more complex, thus implementing Occam's razor. This intuition is visualized in Figure 11.1.

### 1.3 Cross-validation

A popular non-Bayesian model selection criterion is cross-validation. The idea is that you split your data set into $\mathcal{D} = \mathcal{D}_{\text{train}} \cup \mathcal{D}_{\text{val}}$, with disjoint training and validation sets $\mathcal{D}_{\text{train}}$ and $\mathcal{D}_{\text{val}}$. We can then estimate the generalization risk (i.e., the expected loss on unseen data) by training a model on $\mathcal{D}_{\text{train}}$ and then evaluating its error on $\mathcal{D}_{\text{val}}$. This fits the intuition that we are ultimately interested in applying our model to unseen test data $\mathcal{D}_{\text{test}}$, so we want to know how well the model predicts on datapoints it has not seen during training.

In their seminal paper, Fong and Holmes show that the log marginal likelihood on $\mathcal{D}$ is equal to the average validation log likelihood over all possible cross-validation splits, that is,

$$
\log p(\mathcal{D}) = \mathbb{E}_{\mathcal{D}_{\text{train}}, \mathcal{D}_{\text{val}} \sim \operatorname{split}(\mathcal{D})}\big[\log \mathbb{E}_{\theta \sim p(\theta \mid \mathcal{D}_{\text{train}})}[p(\mathcal{D}_{\text{val}} \mid \theta)]\big] \tag{11.4}
$$

where $\operatorname{split}(\mathcal{D})$ is a shorthand for writing a mechanism that first uniformly samples a data set size split $m < N$ and then samples a uniformly random permutation of assigning $N - m$ points to $\mathcal{D}_{\text{train}}$ and $m$ points to $\mathcal{D}_{\text{val}}$. Note that for notational convenience, we have suppressed the explicit conditioning on $\mathcal{M}$, but you can indeed read all the $p(\cdot)$ here as implicitly being $p(\cdot \mid \mathcal{M})$.

Obviously, actually performing this exhaustive cross-validation procedure would require a computational cost scaling combinatorially with the data set size $N$, so nobody would actually compute this in practice. However, we see that with the marginal likelihood, we get the result of this exhaustive procedure by solving just a single integral over the training data set. This is another argument for the marginal likelihood as a model selection criterion: if you believe that cross-validation is a good way to evaluate the potential generalization capabilities of your model, the marginal likelihood will not only compute one cross-validation for you, but *all* of them at the same time!

### 1.4 PAC-Bayes

Another way to study the generalization behavior of Bayesian predictors is to use the framework of PAC-Bayes bounds. While we will get a more thorough introduction to PAC-Bayes bounds in later chapters (specifically in Chapter 22), for now it suffices to say that they are mathematical statements that bound the expected true risk of our (approximate) posterior (which we cannot know because we do not have access to the true data-generating process) with the expected empirical risk that we can actually measure. These bounds generically look something like this:

**Proposition 11.1** (Generic PAC-Bayes bound). *For any (approximate) posterior $q(\theta)$, choice of prior $p(\theta)$, and choice of $\delta \in (0, 1)$, the expected true risk is bounded with probability at least $1 - \delta$ over sampling of data sets $\mathcal{D}$ of size $N$ from the data-generating process as*

$$
\mathbb{E}_{\theta \sim q(\theta)}[\mathcal{L}(\theta)] \leq \mathbb{E}_{\theta \sim q(\theta)}\Big[\hat{\mathcal{L}}(\theta, \mathcal{D})\Big] + \mathcal{C}(q(\theta), p(\theta), N, \delta) \tag{11.5}
$$

Here, $\mathcal{C}(q(\theta), p(\theta), N, \delta)$ is a term that measures the model complexity. In a simple case, this could, for instance, be

$$
\mathcal{C}(q(\theta), p(\theta), N, \delta) = \sqrt{\frac{\mathrm{D}_{\mathrm{KL}}(q(\theta) \,\|\, p(\theta)) + \log \frac{2\sqrt{N}}{\delta}}{2N}} \tag{11.6}
$$

This bound fits several key intuitions: it gets tighter as the size of the data set grows because the model can overfit less; it gets looser if we reduce $\delta$ because then the bound needs to hold with higher probability; and it gets looser as the KL-divergence between posterior and prior grows because then the model can overfit more.

In summary, to get a small bound on the expected risk, you need a posterior that predicts well in terms of empirical risk and at the same time is as simple as possible in terms of the complexity measure $\mathcal{C}$. If this again sounds like Occam's razor to you, you will not be surprised to learn that PAC-Bayes bounds can be formally connected to the marginal likelihood (indeed, this section would probably not be part of this chapter otherwise).

If we take the posterior in the bound to be the true Bayes posterior, Germain et al. derive the following PAC-Bayes bound. Note that the true posterior is often intractable and can only be approximated, in which case the bound will only hold approximately. Note also that it only holds under the technical condition that the log likelihood is sub-Gamma; a sub-Gamma loss is one whose tails are upper-bounded by the tails of a Gamma distribution, essentially ensuring that the loss does not grow unexpectedly fast. This holds, for instance, for Bayesian linear regression with a Gaussian likelihood.

**Proposition 11.2** (Marginal likelihood PAC-Bayes bound). *For any choice of prior $p(\theta)$, and choice of $\delta \in (0, 1)$, and if the negative log likelihood loss $\ell(\theta, \mathcal{D}) = -\log p(\mathcal{D} \mid \theta)$ is sub-Gamma with variance factor $s^2$ and scale $c < 1$, the expected true risk under the Bayes posterior $p(\theta \mid \mathcal{D})$ is bounded with probability at least $1 - \delta$ over sampling of data sets $\mathcal{D}$ of size $N$ from the data-generating process as*

$$
\mathbb{E}_{\theta \sim p(\theta \mid \mathcal{D})}[\mathcal{L}(\theta)] \leq \frac{s^2}{2(1 - c)} - \frac{1}{N} \log\left(\delta\, p(\mathcal{D})\right) \tag{11.7}
$$

We therefore see that maximizing the marginal likelihood directly minimizes this bound on the generalization error, providing another strong (frequentist) argument for why it is a reasonable criterion for model selection. Remember, however, as a caveat, that this result only strictly holds for sub-Gamma likelihoods, such as for linearized Laplace in the regression setting, but not in the case of full Laplace inference in BNNs, especially in the classification setting. For those cases, the bound does not provide a proper guarantee, but still an intuitive argument for why the Occam's razor effect of the marginal likelihood can improve generalization.

## 2. Differentiable marginal likelihood with Laplace

So now that we have convinced ourselves that the marginal likelihood is a great criterion for model selection, we are left with the problem of actually computing (or approximating) it. Indeed, this is one of the main challenges of Bayesian inference, which is why, in practice, the marginal likelihood is not often used for this purpose. However, as promised above, the Laplace approximation has the lucky property that we can actually compute the marginal likelihood in closed form!

To understand how we can do that, we will need to look under the hood of the Laplace approximation in [Equation 7.4b](/blog/laplace-introduction). Let us remind ourselves that we are aiming to approximate the posterior

$$
p(\theta \mid \mathcal{D}) = \frac{p(\theta)\, p(\mathcal{D} \mid \theta)}{p(\mathcal{D})} = \frac{1}{p(\mathcal{D})}\, \tilde{p}(\theta) \tag{11.8}
$$

where we have now written the unnormalized posterior as $\tilde{p}(\theta)$. In the context of model selection, feel free to mentally condition all of these distributions on $\mathcal{M}$ as in Equation 11.1 above. We will omit this conditioning here to not needlessly clutter the notation. Note also that we can choose the regularized risk from [Equation 7.2](/blog/laplace-introduction) to be $\mathcal{L}_\Omega(\theta) = -\log \tilde{p}(\theta)$.

If we approximate $\log \tilde{p}(\theta)$ around a point $\theta_*$, this gives

$$
\log \tilde{p}(\theta) \approx \log \tilde{p}(\theta_*) + \nabla_{\theta_*} \log \tilde{p}(\theta_*)^\top (\theta - \theta_*) - \frac{1}{2} (\theta - \theta_*)^\top \Psi(\theta_*) (\theta - \theta_*) + \mathcal{O}(\theta^3) \tag{11.9}
$$

where $\Psi(\theta)$ is the same Hessian operator as in [Equation 7.5](/blog/laplace-introduction). Note that $\Psi$ is the Hessian of $-\log \tilde{p}(\theta)$, hence the sign change in the Taylor expansion.

If we now choose $\theta_*$ to be a maximizer of the (log) posterior, such that the first-order term vanishes because $\nabla_\theta \log \tilde{p}(\theta) = 0$, and ignore the third and higher order terms, we can approximate $\tilde{p}(\theta)$ with a distribution $q(\theta)$, which we define as

$$
q(\theta) = \frac{1}{Z_q} \exp\left(\log \tilde{p}(\theta_*) - \frac{1}{2} (\theta - \theta_*)^\top \Psi(\theta_*) (\theta - \theta_*)\right) \tag{11.10}
$$

$$
\phantom{q(\theta)} = \frac{\tilde{p}(\theta_*)}{Z_q} \exp\left(-\frac{1}{2} (\theta - \theta_*)^\top \Psi(\theta_*) (\theta - \theta_*)\right) \tag{11.11}
$$

Now, instead of computing the true marginal likelihood $p(\mathcal{D}) = \int \tilde{p}(\theta)\, \mathrm{d}\theta$, we can just approximate it with the normalizer of our approximate distribution, that is $p(\mathcal{D}) \approx q(\mathcal{D}) = Z_q$.

Since we see from the quadratic form in the exponential that $q(\theta)$ is multivariate Gaussian with mean $\theta_*$ and precision matrix $\Psi(\theta_*)$, we can look up the normalizing constant, which is $\sqrt{(2\pi)^P \det \Psi(\theta_*)^{-1}}$, where $P$ is the dimensionality of the parameter space. This means that $\tilde{p}(\theta_*)/Z_q = (2\pi)^{-P/2} \det \Psi(\theta_*)^{1/2}$. Therefore, our approximate log marginal likelihood is

$$
\log Z_q = \log q(\mathcal{D}) = \log \tilde{p}(\theta_*) - \frac{1}{2} \log \det \Psi(\theta_*) + \frac{P}{2} \log 2\pi \tag{11.12}
$$

$$
\phantom{\log Z_q = \log q(\mathcal{D})} = \log p(\theta_*) + \log p(\mathcal{D} \mid \theta_*) - \frac{1}{2} \log \det \Psi(\theta_*) + \text{const} \tag{11.13}
$$

Note that in the last line, we assumed that the number of parameters $P$ is the same across the different models $\mathcal{M}$ that are being compared. If the model selection is meant to be performed across models with different numbers of parameters, this term naturally is not constant and still needs to be considered in the marginal likelihood.

### 2.1 Computational considerations

Similar to the inversion $\Psi^{-1}$ discussed in previous chapters, the determinant $\det \Psi$ also has a computational cost of $\mathcal{O}(P^3)$ if the matrix is of size $P \times P$. As discussed before, this can get very expensive when the dimensionality of the parameter space is large, that is, for large neural network models. However, luckily, we can use some computational tricks and approximations to reduce the computational cost, such as linearization and the empirical Fisher information, as well as diagonal or low-rank approximations (see [Chapter 8](/blog/linearized-laplace-approximations) and Chapter 40 for details). Since none of these considerations are unique to the marginal likelihood computation, we will not discuss them at length in this chapter.

### 2.2 Post-hoc vs. online model selection

When selecting models using the marginal likelihood, the most naïve way is to perform *post-hoc* model selection. For instance, we can train two models, $\mathcal{M}_0$ and $\mathcal{M}_1$, and then compute their respective (log) marginal likelihoods. For illustration purposes, let us say that $\mathcal{M}_0$ is a fully-connected neural network and $\mathcal{M}_1$ is a convolutional neural network. We train them both on some image data set (e.g., MNIST) and then compute $\log q(\mathcal{D} \mid \mathcal{M}_0) - \log q(\mathcal{D} \mid \mathcal{M}_1)$. If this quantity is positive, we select $\mathcal{M}_0$, if it is negative, we select $\mathcal{M}_1$. Note that this difference between log marginal likelihoods is equivalent to the likelihood ratio test, which, according to the famous Neyman-Pearson lemma, is the uniformly most powerful hypothesis test.

This selection approach gives us all the benefits of the marginal likelihood described in the previous section, but it still requires that we train each of the different models we want to test. Indeed, for selecting some parts of the model, we can do much better than that! While the neural network architecture is a discrete choice that we have to test post hoc, there are hyperparameters of the neural network with respect to which we can actually compute gradients of the marginal likelihood and then optimize them *online*. These include, for instance, the variance(s) of the prior or the likelihood noise. We will denote as $\mathcal{M}^\partial$ the subset of parameters for which gradients $\nabla_{\mathcal{M}^\partial} \log q(\mathcal{D} \mid \mathcal{M})$ exist. We can then optimize these parameters by performing simple gradient ascent like

$$
\mathcal{M}^\partial \leftarrow \mathcal{M}^\partial + \gamma \nabla_{\mathcal{M}^\partial} \log q(\mathcal{D} \mid \mathcal{M}) \tag{11.14}
$$

where $\gamma$ is a step size. This allows us to select all these model hyperparameters within a single training run, without the need to train several models, as would be the case for approaches such as cross-validation.

However, this approach comes with a few caveats: First, recall that the marginal likelihood depends on the Hessian $\Psi(\theta_*)$, so on the second derivatives of the loss. If we want to take gradients of the marginal likelihood, we need to ensure that these are differentiable with respect to the hyperparameters, which is not true for all activation functions. Particularly, it is not true for the ReLU activation function, so we need to ensure to use smoother ones if we want to perform online model selection (e.g., sigmoid, tanh, Swish, GeLU, ELU, etc.). Second, since the marginal likelihood depends on the entire data set $\mathcal{D}$, computing it requires an entire pass over the data set, so in deep-learning parlance, one epoch. Since the best parameters $\theta_*$ generally depend on the choice of $\mathcal{M}^\partial$, we typically interleave the training, that is, we train $\theta$ for one or more epochs and then make one or several gradient steps on the marginal likelihood as written above, each of which corresponds to an additional epoch on the data. Depending on the frequency of these updates, the training will therefore require more epochs; in practice, typically around twice as many. Finally, dropping the first-order term in the Taylor expansion above required $\theta_*$ to be a true optimum of the loss, where the gradients vanish, but one might wonder whether standard optimizers actually find such optima in deep learning. Indeed, in practice, the optima we find do not truly have zero gradients everywhere. However, it has been shown empirically that this generally does not impair the model selection with the marginal likelihood and there are even some theoretical arguments for why this might be the case.

### 2.3 Simple example

As a simple illustrative example of online model selection with the marginal likelihood, we will consider a small fully-connected neural network for a synthetic 2D classification task. We place a Gaussian prior over the weights and we assume that the prior variance is shared within each layer. That is, the $i$th weight in the $\ell$th layer will have the prior $p(\theta_{\ell i}) = \mathcal{N}(0, \sigma_\ell^2)$. Our hyperparameters to select are now these layerwise variances, so $\mathcal{M}^\partial = \{\sigma_\ell^2\}_{\ell=1}^L$.

We see in Figure 11.2 that our estimate of the marginal likelihood increases monotonically over the course of training and seems to converge to a local optimum. We also see that the prior variances indeed change during training and also seem to converge. The final model achieves a lower training accuracy compared to a naïvely trained model, but a higher test accuracy. This indicates that our selected model is better regularized and overfits less, in line with the Occam's razor effect of the marginal likelihood. The visual smoothness of its decision boundary supports this conclusion.

### 2.4 On the risk of overfitting

Based on the previous example and our arguments above, you may now be convinced that the Laplace marginal likelihood will always select the best model for you, no matter the circumstances. Unfortunately, you would be wrong about that. We do not want to hide the caveat that maximum marginal likelihood (ML-II), much like standard maximum likelihood (ML-I), carries the inherent risk of overfitting. In our previous examples, such as choosing between two model architectures or optimizing layerwise prior variances, this has not been apparent because the number of models compared (or number of hyperparameters optimized) was small compared to both the number of parameters of the model and the number of datapoints. However, if we were to optimize a number of hyperparameters (or compare a number of models) larger than $P$ and $N$, we may well overfit the model to the data.

In such cases, just like in standard maximum likelihood, one remedy is to make the hyperprior $p(\mathcal{M})$ in Equation 11.2 more informative and thus regularize the optimization. We could, for instance, have a separate prior for each weight $p(\theta_{\ell i}) = \mathcal{N}(\mu_{\ell i}, \sigma_{\ell i}^2)$ that we optimize with the marginal likelihood, but then have strong hyperpriors $p(\mu)$ and $p(\sigma^2)$ that regularize these two parameters to some reasonable values unless the marginal likelihood really provides strong evidence for different ones. For a more in-depth discussion on the risks of overfitting with the marginal likelihood in model selection and the use of hyperpriors, see Ober et al.

Another remedy, proposed by Lotfi et al., is to compute the marginal likelihood not on the whole data set, but only on a subset, similar to cross-validation. The authors call this the *conditional log marginal likelihood* (CLML). While this can in practice indeed reduce the overfitting effects, it inherits a lot of the computational challenges of standard cross-validation, most importantly the need to choose a validation split or to perform the procedure several times across different splits.

### 2.5 Connection to flat minima

A lot of the arguments we made above in [Section 1](#1-marginal-likelihood-for-model-selection) hold for the true marginal likelihood $p(\mathcal{D})$. Based on some of the arguments in [Chapter 7](/blog/laplace-introduction), you might wonder whether our approximation $q(\mathcal{D})$ is not too crude for model selection purposes. If the true BNN posterior has exponentially many modes, each of which has potentially a non-Gaussian geometry, should we really believe that approximating the marginal likelihood with a single Gaussian on one mode is enough to judge the quality of the model? Indeed, the proof of the metaphorical pudding is in the eating, and we will see in the following section that the Laplace marginal likelihood can effectively be used for many model-selection use cases in practice. However, before we get to the empirics, there is one more conceptual argument we can offer to hopefully appease the skeptical reader.

If we have another look at our Laplace marginal likelihood criterion in Equation 11.13, we see that it has three parts: the prior, the likelihood, and the log determinant of the Hessian. That means that models will achieve a large marginal likelihood estimate if they are probable under the prior, fit the data well (in terms of the likelihood), and have a small determinant of the Hessian. The latter of these is clearly the most cryptic. What does a small determinant mean? Recall that we assume that we are at a local optimum, or have at least linearized our network or added a sufficiently strong prior, such that the Hessian is positive definite. That means that all its eigenvalues are positive. Since the determinant is the product of the eigenvalues, a small determinant means that the eigenvalues of the Hessian are small, which in turn means that the loss function (our negative log posterior) has low curvature in the region around $\theta_*$: it is relatively flat.

The idea that such flat minima can lead to better generalization has been around for a while. In fact, it is quite intuitive, since it essentially means that small changes in $\theta_*$ do not lead to large changes in the loss, so even if we are a bit off from the true optimum and even if the loss landscape shifts a bit due to distribution shift in the test data, we will probably still achieve a relatively low test error. This intuition is also sketched in Figure 11.3. If this combination of train error (likelihood) and complexity measure (flatness) sounds like a PAC-Bayes bound to you, you are on the right track: flat minima have indeed been connected to PAC-Bayesian results. Moreover, the deep learning community has embraced flatness-encouraging training criteria (similar to our marginal likelihood) for its purposes, such as the famous sharpness-aware minimization (SAM) or its Bayesian counterpart (bSAM).

## 3. Use cases

As we have seen above, the Laplace marginal likelihood can be effectively used to select differentiable hyperparameters online, such as the prior variances or the likelihood noise, and to compare non-differentiable design choices post hoc, such as neural network architectures. These capabilities have been discovered by Immer et al. for modern deep learning models, and they have shown that this type of model selection is often cheaper and more effective than cross-validation. However, this type of hyperparameter tuning is by far not the only way the marginal likelihood can be used for model selection in deep learning. In recent years, different use cases have been developed, some of which have the potential to unlock entirely new application areas. While we cannot possibly provide a comprehensive overview of all of them, we will introduce a selection of the most interesting and creative ones in this section.

### 3.1 Feature selection

A common use case for model selection in Gaussian process models is feature selection via the automatic relevance determination (ARD) kernel (see also Chapter 23). This is a kernel in which each feature dimension has its own associated length scale. These length scales can then be tuned using the marginal likelihood. One can perform a similar kind of feature selection in BNNs with the Laplace approximation, by performing model selection on the input weights. This is naturally more reasonable for data where the different input features have distinct semantic meaning, such as tabular data, than where they do not, such as images. One can even extend this idea to neural additive models (NAMs), that is, models where each input feature is passed to a separate neural network module, by performing model selection on the entire modules. Bouchiat et al. have shown that the Laplace marginal likelihood provides an effective way to select features in Bayesian NAMs and even further improve their interpretability through its Occam's razor effect.

### 3.2 Neural network pruning

The aforementioned feature selection, in its simplest implementation, amounts to removing weights from the input layer. This suggests the idea that one might also be able to remove weights from deeper layers. Indeed, this is the basic premise of the research field of neural network pruning. There are two major approaches to pruning: unstructured pruning, where weights across the whole weight matrix are removed, and structured pruning, where entire rows or columns of the weight matrix are removed (this corresponds to removing neurons from the layer). Note that while the latter approach is more aggressive, it is the only one that immediately leads to computational gains, since the former approach just makes the matrix more sparse, but not smaller. Dhahri et al. have shown that the Laplace marginal likelihood can be used to improve pruning in both settings, through its Occam's razor effect, which encourages the neural networks to only use just as many weights as are needed for a given task. They have also shown that the Laplace posterior offers a simple yet effective pruning criterion: the log posterior density evaluated at 0.

### 3.3 Invariance learning

While the previous two use cases are still intuitively connected to our original model selection examples, as well as to existing applications in other models such as Gaussian processes, Immer et al. propose to use the marginal likelihood for a more creative task: learning invariances from data. While invariances are commonplace in the context of designing invariant neural network architectures by hand (e.g., convolutional neural networks), there are many applications where invariances may be present in the data but the user does not know them. Following the approach from van der Wilk et al., Immer et al. suggest using the following parameterization of a generic invariant function:

$$
\hat{f}(x, \theta, \eta) = \mathbb{E}_{x' \sim p(x' \mid x, \eta)}[f(x', \theta)] \tag{11.15}
$$

Here, $f(\cdot)$ is the neural network, $\hat{f}(\cdot)$ is the desired invariant function, $p(x' \mid x, \eta)$ is a data augmentation distribution, with respect to which the function should be invariant, and $\eta$ are hyperparameters controlling this augmentation distribution. The Laplace marginal likelihood can now be used to select $\eta$ online during training and therefore enables learning a function that discovers the invariances directly from the data within a single training run. Immer et al. show that this can faithfully recover known invariances and can drastically improve data efficiency on real data sets.

### 3.4 Probing

In addition to the bona fide model selection use cases introduced above, finally, the marginal likelihood can even be used for applications that, on the surface, do not look like model selection, such as probing. Probing is a common interpretability tool in language models, and it tries to answer the question of whether the latent representations of these models encode certain properties of their inputs. For instance, people might wonder "Does BERT encode the concept of verb tense?". To answer this, there is a long line of work trying to take these latent encodings and fitting different simple readout functions to them, such as linear functions, to predict the property of interest, in this case, verb tense. But what if the encodings do not encode the property linearly but quadratically? Then the linear probe might not perform well, but arguably, the property is still encoded. However, a quadratic model is more complex than a linear one, so maybe one should count this property as less well encoded than in a set of encodings where a linear probe would suffice. That again sounds suspiciously like Occam's razor, and indeed Immer et al. have shown that one can treat the problem of *jointly* selecting encodings and probes to predict the desired property as a model selection problem and use the Laplace marginal likelihood for a fair apples-to-apples comparison between different models. This shows that the tools presented in this chapter are much more widely applicable than one might naïvely expect, when one is a bit more creative in the interpretation of what *model selection* might look like.
